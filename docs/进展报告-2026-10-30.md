**过程中新修的坑（#8、#9）**：

1. **instances.port 全表 UNIQUE 会阻止端口复用**——回收再分配是平台核心语义，历史记录不能永久占端口。改为部分唯一索引：只对 `status IN ('creating','running','stopped')` 的实例唯一，recycled/failed 不占坑
2. **5 并发初始化时健康检查误判**——2 核 CPU 上 5 个 MySQL 同时首次初始化超 1 分钟，原 10次×2s 的 ping 窗口必超时（第一轮实测 10/10 全失败）。改为 40次×3s（2 分钟窗口）后 10/10 全成功
3. **失败记录缺失**——端口冲突重试耗尽后端口已归还，原逻辑误判"从未租过端口"而不写失败记录，教师端看不到失败原因。已修：只要租过端口就留 failed 记录

## 十、P1 扩展：学生失误实时可见（2026-10-30 17:20）

在原 8 个任务之外新增的能力——让平台不止"发环境"，还能"看见学生怎么错"。

**实现**：容器开 MySQL `general_log`（学生每条 SQL 落盘到数据卷）→ `insights.py` 按字节偏移增量采集 → `sqlglot` 解析判错 → 教师端"错题诊断"按钮展示。

| 检测类型 | 判定方式 | 价值 |
|---|---|---|
| 表不存在（unknown_table） | 解析出表名，比对 information_schema 实际表清单 | 等价 ERROR 1146，学生最常犯 |
| 危险操作（dangerous） | AST 检 UPDATE/DELETE 无 WHERE | 防误删改全表 |
| 写法提示（hint） | SELECT * / JOIN 缺 ON（笛卡尔积） | 教学纠偏 |
| 语法错误（syntax_error） | sqlglot 解析失败 / 解析成非语句节点 | **注意：MySQL 不把 1064 写 general log，实际抓到的很少** |

**验收（实验单 6，3 名学生真实执行）**：采集 51 条 SQL，三类失误全部命中；API `GET /api/labs/{id}/errors` 公网返回正确；页面按钮可用。

**已知限制与取舍**：

1. **1064 纯语法错误抓不到**（实测：语法解析失败时 MySQL 不写 general log，日志行数不增加）。补救方案：二期上"轻量 MySQL 协议代理"或开 performance_schema 的 `events_statements_history_long`（需评估 256M 容器内存）
2. general_log 会持续增长，目前未做轮转（2 小时课堂量级几 MB，可接受）；上线前需加按大小轮转或只保留当日
3. 采集在"点击错题诊断"时触发（手动），因为要 docker exec 查表清单；后续可改为定时任务
