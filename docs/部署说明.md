## 一、组件清单

| 组件 | 实现 | 配置位置 |
|---|---|---|
| 应用服务 | systemd 托管 uvicorn，`Restart=always` | `/etc/systemd/system/mysql-lab.service` |

## 二、为什么用 systemd 而不是 docker-compose

交接文档建议 docker-compose，实测后改用 systemd，理由：

1. **实验容器本来就不是 compose 管的**——学生容器是平台运行时通过 Docker SDK
   动态创建/销毁的，compose 能管的只有 app 本身一层
2. app 直接跑在宿主机（未容器化），没有跨多服务编排需求；为单进程引入
   镜像构建 + compose 栈是负收益（2核4G 上省 200MB 内存）
3. systemd 的 `Restart=always` + `After=docker.service` 恰好覆盖验收要求
   （重启自动起来、依赖就绪），且无需额外构建产物

说明口径：**"评估过 docker-compose，因为实验容器是运行时动态创建的，
静态编排只覆盖 app 一层；单进程宿主机部署 + systemd 托管更轻，
把内存留给学生实例"** ——这是取舍，不是不会。

## 六、从零部署（Ubuntu 24.04 实测，2026-10-31）

4核8G 那台（47.120.71.41）是全新 Ubuntu 24.04，与旧机的 Alibaba Cloud Linux 步骤不同，
按下面顺序执行可一次到位：

```bash
# 1) 系统与 Docker（阿里云内网源已预置，无需换源）
apt-get update -y
apt-get install -y docker.io python3.12-venv python3-pip
systemctl enable --now docker

# 2) 镜像加速（docker.io 直连会被拒）
#    把可用的 registry-mirrors 写进 /etc/docker/daemon.json 后 restart docker

# 3) 关键：内核 AIO 上限。不设置的话第 25 个实例起容器会反复重启
sysctl -w fs.aio-max-nr=1048576
echo "fs.aio-max-nr = 1048576" > /etc/sysctl.d/99-mysql-lab.conf

# 4) 2G swap（无 swap 时高密度实例会把内存打满导致 Docker daemon 超时）
dd if=/dev/zero of=/swapfile bs=1M count=2048 && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo "/swapfile none swap sw 0 0" >> /etc/fstab
echo "vm.swappiness = 10" > /etc/sysctl.d/99-swap.conf && sysctl -p /etc/sysctl.d/99-swap.conf

# 5) 代码与依赖
mkdir -p /root/mysql-lab && cd /root/mysql-lab     # 放 app/ scripts/ templates_sql/
python3 -m venv venv
venv/bin/pip install -i https://mirrors.aliyun.com/pypi/simple/ -r requirements.txt

# 6) 密钥：首次启动会自动生成 .env 并打印提示（也可手工预置 32+ 字节随机值）

# 7) systemd（模板见 deploy/mysql-lab.service，改 Environment=LAB_PUBLIC_HOST）
cp deploy/mysql-lab.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now mysql-lab

# 8) 金镜像（一次性，4 核约 40s）
venv/bin/python scripts/make_gold.py

# 9) 验收
venv/bin/python scripts/stress_test.py --n 30
```

**踩过的两个坑（与平台无关，但会卡住部署）**

1. **docker.io 直连被拒**：`failed to resolve reference ... connection refused`，
   必须配 `registry-mirrors`（见第 2 步）
2. **长连接被链路掐断**：这台机器上 apt/scp/长 ssh 会话经常在 30 秒左右被 reset
   （sshd 日志只有正常的 session closed，没有报错）。对策是把长任务交给 systemd：
   ```bash
   systemd-run --unit=xxx --no-block /bin/bash -c "长命令 > /root/xxx.log 2>&1"
   ```
   ssh 只负责启动和轮询日志，断线不影响任务；几十 KB 以上的文件用 tar 打包再传。

## 八、重装暴露的四个坑（都已修，别再踩）

这四个问题的共同点：**首次部署全部正常，只在"重启"或"换台机器重装"时才暴露**，
所以第一次搭环境时一个都测不出来。

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 重启后全班实例消失，界面仍显示"运行中" | `restart_policy=on-failure`，而关机时 mysqld 收到 SIGTERM 正常退出（code 0），策略不触发 | 改为 `unless-stopped`（机器重来自动拉起，教师手动 stop 仍不拉起） |
| 2 | 容器一直 `Restarting (1)`，日志 `find: /var/lib/mysql/<db>: Permission denied` | `cap-drop ALL` 把 `DAC_OVERRIDE` 一起去掉，容器内 root 进不去属主为 mysql、权限 750 的库目录。**首次启动时库目录还不存在，所以不报错** | `MYSQL_REQUIRED_CAPS` 补 `DAC_OVERRIDE` |
| 3 | 实验单到期不自动回收 | `/etc/cron.d` 里的解释器写的是系统 `python3.11`，而依赖装在 `venv` 里；换台干净机器就 import 失败（本机因历史残留掩盖了这个问题） | cron 模板改用 `/root/mysql-lab/venv/bin/python` |
| 4 | 学生端显示一个连不上的地址 | `deploy/mysql-lab.service` 把 `LAB_PUBLIC_HOST` 写死成压测机 IP | 模板留空，部署时用 drop-in 覆盖 |

**验收口径也要补一条**：重启验证不能只看"服务起来了吗"和"元数据丢没丢"，
必须**进容器执行一条 SQL**。容器 `Up` 不代表可用（坑 2 就是 Up 之后立即进入重启循环）。

```bash
docker inspect <容器> --format "Restarts={{.RestartCount}}"   # 必须为 0
docker exec <容器> mysql -h127.0.0.1 -u<学生账号> -p<密码> -e "select 1"
```



## 九、启用 HTTPS（v1.0.3，前置 Nginx）

> 默认部署是 HTTP 直连 8000。教学内网可以先不启；**只要走公网，教师登录密码和学生练习
> 记录就是明文过网**，这一节就是补这个的。全流程约 15 分钟，一次配好。

### 9.1 前提（三条缺一不可）

1. 一个解析到服务器公网 IP 的**域名**。Let's Encrypt 不给裸 IP 签证书（需核实：IP 证书
   仅部分 CA 商业签发，教学场景不值得花这个钱）；没有域名就去阿里云/腾讯云买一个，几块钱一年。
2. 安全组放通 80、443；**8000 端口从安全组撤掉**（第 5 步会收回本机回环）。
3. 服务器装 nginx：Anolis 3 `dnf install nginx`，Ubuntu `apt install nginx`。

### 9.2 步骤

```bash
# 1) 证书（以 certbot 为例；Anolis 需要 EPEL：dnf install epel-release）
dnf install -y certbot python3-certbot-nginx        # Ubuntu: apt install certbot python3-certbot-nginx
mkdir -p /var/www/certbot
# 先放一个只含 80 端口的最小配置让 certbot 能应答，跑完签发再换完整模板
certbot certonly --webroot -w /var/www/certbot -d <你的域名>

# 2) 完整站点配置（443 + 80 跳转 + 反代）
cp deploy/nginx-mysql-lab.conf /etc/nginx/conf.d/mysql-lab.conf
sed -i 's/<域名>/你的域名/g' /etc/nginx/conf.d/mysql-lab.conf
nginx -t && systemctl enable --now nginx

# 3) 告诉应用"前面有反代"：限流器开始信任 X-Forwarded-For，审计日志记到真实学生 IP
systemctl edit mysql-lab
#   写入：
#   [Service]
#   Environment=LAB_TRUST_PROXY=true
systemctl restart mysql-lab && curl -s localhost:8000/healthz

# 4) 关键收口：uvicorn 从"全网卡 0.0.0.0:8000"收回本机回环，公网只能走 443
systemctl edit mysql-lab
#   追加 ExecStart 覆盖（systemd 覆盖 ExecStart 必须先清空再写）：
#   [Service]
#   ExecStart=
#   ExecStart=/root/mysql-lab/venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
systemctl daemon-reload && systemctl restart mysql-lab

# 5) 自动续期验证（证书 90 天有效，certbot 装好自带 timer）
certbot renew --dry-run
systemctl list-timers | grep certbot
```

### 9.3 验证清单（照抄执行）

```bash
curl -sI https://<你的域名>/healthz            # 200，且带 Strict-Transport-Security 头
curl -sI http://<你的域名>/healthz             # 301 → https
curl -sI https://<你的域名>/api/templates     # Cache-Control: no-store（应用层给的，证明反代没吞头）
ss -lntp | grep -E ':8000|:443'               # 8000 只应绑 127.0.0.1；443 绑 0.0.0.0
```

最后一条**必做**：8000 若还绑在 0.0.0.0，等于 TLS 白配——公网直连 8000 全部绕过。

### 9.4 学生不受影响的原因

学生连的是 `33001-33100` 的 **MySQL 协议**，直连容器端口，不经过 Nginx。
HTTPS 只保护教师端和学生端两个网页。学生通道的防线是另一套：库级账号授权 +
16 位随机密码 + 容器 cap 收敛（交付说明书第三节第 1 条取舍）。

## 十、弹性部署：按量开机即用、下课释放（v1.0.3）

> 适用场景：不是长期租一台服务器，而是**开课时临时开一台、下课就释放**。
> 核心思路：把"装好一切的机器"做成**阿里云自定义镜像**，之后每次开课 = 用该镜像
> 开一台按量实例，开机约 1 分钟服务就绪，下课释放，只为上课的几小时付费。
> （按量 2核4G 约 ¥0.3-0.5/小时，需核实控制台实时价；一节 2 小时课不到 1 块钱。）

### 10.1 一次性：做自定义镜像（约 15 分钟）

```bash
# 1) 买一台最小按量 ECS（2核4G 即可，Anolis 3 / Ubuntu 24.04 均可）
#    控制台「实例自定义数据」注入 bootstrap.sh 的全文，或 SSH 上去手动执行：
sudo WITH_GOLD=1 bash deploy/bootstrap.sh
#    脚本自动完成：AIO 参数 → swap → Docker + mysql:8.0 预拉 → venv 依赖
#    → systemd 托管（LAB_PUBLIC_HOST=auto）→ 金镜像 → 冒烟验收

# 2) 脚本跑完会提示最后两步：
systemctl stop mysql-lab        # 镜像里不留运行态
#    控制台 -> 该实例 -> 磁盘与镜像 -> 创建自定义镜像
# 3) 镜像创建完成后，这台"做镜像用的"按量实例直接释放，不再计费
```

镜像里有什么：Docker + mysql:8.0 镜像 + venv 全依赖 + 代码 + 金镜像 + systemd（enabled）。
**密钥不在镜像里**——bootstrap 不写任何密钥，APP_SECRET 由应用每台机器首次启动自动生成，
"用完即释放"场景下每台机器一套新密钥，学生密码随元数据全新生成，互不影响。

### 10.2 每次开课（约 2 分钟）

```text
控制台 -> 创建实例 -> 自定义镜像（选上一步做的）-> 按量付费 -> 2核4G -> 分配公网 IP
  -> 开机后约 1 分钟服务自启
  -> LAB_PUBLIC_HOST=auto 生效：应用启动时自己从云 metadata 探测公网 IP，
     CSV 导出和学生端回显自动用新机器的地址，零手工配置
  -> 记下新机器公网 IP，教师端开课
```

下课：控制台「释放」实例即可。**元数据、学生数据、密钥随机器一起消失**——
如果你需要留练习报告，下课释放前先导出 CSV（这是唯一需要记得的事）。

### 10.3 代码更新后同步镜像

```bash
# 在任意一台由镜像开出的实例上：
cd /root/mysql-lab && git pull && systemctl restart mysql-lab
venv/bin/python scripts/task9_test.py http://127.0.0.1:8000   # 验收
# 验收全绿后：stop -> 重新「创建自定义镜像」（可替换旧镜像版本）-> 释放
```

### 10.4 边界与注意

- **数据不跨机器**：弹性模式下没有"上次的实验单"，审计日志、练习记录都随实例消失。
  要留痕就下课释放前导出。长期服务器模式（第七节）不受影响。
- **端口与安全组**：安全组模板一次配好（8000 或 443 + 33001-33100 限源），
  每台新实例挂同一个安全组，不用每次改。
- **HTTPS**：弹性场景每台机器 IP 都在变，Let's Encrypt 域名证书做不了泛 IP——
  弹性模式建议维持 HTTP（内网/校园网可达时风险可控），或配一个固定域名
  轮流解析到当次实例 IP（DNS TTL 设短）。固定长期服务器才上第九节的 HTTPS 流程。
- `LAB_PUBLIC_HOST=auto` 只在云主机内生效（metadata 服务仅内网可达）；本机开发
  没有该服务，自动回退为空并用请求 Host 兜底，不会报错。
