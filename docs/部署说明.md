## 一、组件清单

| 组件 | 实现 | 配置位置 |
|---|---|---|
| 应用服务 | systemd 托管 uvicorn，`Restart=always` | `/etc/systemd/system/mysql-lab.service` |
| Docker | 开机自启（实验容器由 SDK 动态创建，非 compose 管理） | `systemctl is-enabled docker` |
| 对账定时 | cron 每小时：到期回收 + 僵尸清理 | `/etc/cron.d/mysql-lab-reconcile` |
| 内存兜底 | 2G swapfile（swappiness=10），防学生大查询触发 OOM | `/swapfile` + `/etc/fstab` |
| 日志 | `/var/log/mysql-lab/app.log`，weekly/20M 轮转×8 | `/etc/logrotate.d/mysql-lab` |
| 元数据 | SQLite `data/app.db`（WAL），随磁盘持久化 | 重启后 16 单/84 实例/3 用户/5 模板完整 |

## 二、为什么用 systemd 而不是 docker-compose

交接文档建议 docker-compose，实测后改用 systemd，理由：

1. **实验容器本来就不是 compose 管的**——学生容器是平台运行时通过 Docker SDK
   动态创建/销毁的，compose 能管的只有 app 本身一层
2. app 直接跑在宿主机（未容器化），没有跨多服务编排需求；为单进程引入
   镜像构建 + compose 栈是负收益（2核4G 上省 200MB 内存）
3. systemd 的 `Restart=always` + `After=docker.service` 恰好覆盖验收要求
   （重启自动起来、依赖就绪），且无需额外构建产物

说明话术：**"评估过 docker-compose，因为实验容器是运行时动态创建的，
静态编排只覆盖 app 一层；单进程宿主机部署 + systemd 托管更轻，
把内存留给学生实例"** ——这是取舍，不是不会。

## 五、重启演练 / 灾难恢复

- 数据全部在 `/root/mysql-lab/data/`（app.db + labs/ 数据卷），备份即拷贝该目录
- **`.env` 里的 `APP_SECRET` 必须一起备份**——它是学生库密码的解密密钥，
  丢了即使数据库还在也解不开密码（只能在教师端逐个重置）
- 重建机器：装 Docker + python → `git clone` → 拷回 data/ 与 .env →
  复制本目录配置 → `systemctl enable --now mysql-lab`

## 六、从零部署（Ubuntu 24.04 实测，2026-10-31）

4核8G 那台（47.120.71.41）是全新 Ubuntu 24.04，与旧机的 Alibaba Cloud Linux 步骤不同，
按下面顺序执行可一次到位：

```bash
# 1) 系统与 Docker（阿里云内网源已预置，无需换源）
apt-get update -y
apt-get install -y docker.io python3.12-venv python3-pip
systemctl enable --now docker

# 2) 镜像加速（docker.io 直连会被拒）
#    把可用的 registry-mirrors 写进 /etc/docker/daemon.json 后 restart docker

# 3) 关键：内核 AIO 上限。不设置的话第 25 个实例起容器会反复重启
sysctl -w fs.aio-max-nr=1048576
echo "fs.aio-max-nr = 1048576" > /etc/sysctl.d/99-mysql-lab.conf

# 4) 2G swap（无 swap 时高密度实例会把内存打满导致 Docker daemon 超时）
dd if=/dev/zero of=/swapfile bs=1M count=2048 && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo "/swapfile none swap sw 0 0" >> /etc/fstab
echo "vm.swappiness = 10" > /etc/sysctl.d/99-swap.conf && sysctl -p /etc/sysctl.d/99-swap.conf

# 5) 代码与依赖
mkdir -p /root/mysql-lab && cd /root/mysql-lab     # 放 app/ scripts/ templates_sql/
python3 -m venv venv
venv/bin/pip install -i https://mirrors.aliyun.com/pypi/simple/ -r requirements.txt

# 6) 密钥：首次启动会自动生成 .env 并打印提示（也可手工预置 32+ 字节随机值）

# 7) systemd（模板见 deploy/mysql-lab.service，改 Environment=LAB_PUBLIC_HOST）
cp deploy/mysql-lab.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now mysql-lab

# 8) 金镜像（一次性，4 核约 40s）
venv/bin/python scripts/make_gold.py

# 9) 验收
venv/bin/python scripts/stress_test.py --n 30
```

**踩过的两个坑（与平台无关，但会卡住部署）**

1. **docker.io 直连被拒**：`failed to resolve reference ... connection refused`，
   必须配 `registry-mirrors`（见第 2 步）
2. **长连接被链路掐断**：这台机器上 apt/scp/长 ssh 会话经常在 30 秒左右被 reset
   （sshd 日志只有正常的 session closed，没有报错）。对策是把长任务交给 systemd：
   ```bash
   systemd-run --unit=xxx --no-block /bin/bash -c "长命令 > /root/xxx.log 2>&1"
   ```
   ssh 只负责启动和轮询日志，断线不影响任务；几十 KB 以上的文件用 tar 打包再传。
